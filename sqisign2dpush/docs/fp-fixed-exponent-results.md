固定指数べき乗の事前生成実装（2026-09-08）

各レベルの `fp_exp3div4` と `fp_sqrt` を、事前生成した `fp_exp.c` に移した。`fp_inv` と `fp2_sqrt` は既存の呼び出しを通してこの実装を使用する。体の表現、Montgomery 定数、外部 API、指数自体は変更していない。

実行時に指数バイト列を読みながら window を探索する処理を除去し、平方算の回数と乗算する奇数冪の添字を C ソースに固定した。平方算の連続部分は定数回のループで表現する。秘密入力に依存する分岐やテーブル添字は追加していない。平方根には `(p+1)/4` 専用の手順を使う。

[生成スクリプト](../scripts/gen_fp_fixed.py) は Python 標準ライブラリだけで動き、各手順が目的の整数指数になることも検証する。通常のビルドではチェックイン対象の C ファイルを使うため Python は不要。

```sh
python3 scripts/gen_fp_fixed.py
python3 scripts/gen_fp_fixed.py --check
```

幅 3〜6 の候補を測定し、lvl1 の `(p−3)/4` は幅 4、平方根は幅 3、lvl3/lvl5 は両方幅 5 を選んだ。必要な最大の奇数冪までだけを前計算するため、使わないテーブル末尾は生成しない。この選択は今回の CPU と 64-bit ref バックエンドに対するもの。最適な加算鎖であるとは主張しない。

| レベル | `(p−3)/4` 現行→生成後 | `(p+1)/4` 現行→生成後 |
|---|---|---|
| 1 | 207S+165M → 252S+64M | 207S+78M → 252S+34M |
| 3 | 371S+84M → 371S+84M | 306S+117M → 371S+44M |
| 5 | 505S+105M → 505S+105M | 417S+156M → 505S+53M |

S は平方算、M は乗算。lvl1 の変更前 `(p−3)/4` にある定数 1 の Montgomery 変換はこの回数に含めない。lvl3/lvl5 の `(p−3)/4` は演算回数が同じでも、指数探索の処理が不要になる。平方根では平方算を増やして乗算を減らすため、S/M の速度比によって効果が変わる。

**同条件での変更前後比較**

Intel Core i9-11900、GCC 11.4.0、`-O3 -funroll-loops -flto`。両実装を同じフラグで独立した共有ライブラリにビルドし、1 CPU に固定したプロセスから測った。固定 seed の異なる入力 64 個を使い、1,000 回の C 内ループを 9 ラウンド実行、測定順をシャッフルして中央値を採った。結果を戻り値として消費し、呼び出しが消去されないようにした。Fp2 平方根には平方剰余を入力した。

| 演算 | lvl1 変更前→変更後 | lvl3 変更前→変更後 | lvl5 変更前→変更後 |
|---|---:|---:|---:|
| `fp_exp3div4` | 8.948→7.378 µs（17.6%短縮） | 25.875→25.286 µs（2.3%短縮） | 59.029→55.081 µs（6.7%短縮） |
| `fp_sqrt` | 6.672→6.559 µs（1.7%短縮） | 24.151→21.721 µs（10.1%短縮） | 53.515→47.106 µs（12.0%短縮） |
| `fp_inv` | 9.096→7.382 µs（18.8%短縮） | 26.053→25.541 µs（2.0%短縮） | 59.300→55.400 µs（6.6%短縮） |
| `fp2_sqrt` | 16.107→14.904 µs（7.5%短縮） | 51.081→48.855 µs（4.4%短縮） | 114.566→104.238 µs（9.0%短縮） |

生データ・ビルドフラグ・変更前 `fp.c` のハッシュは [JSON](fp-fixed-exponent-results.json) に記録した。周波数固定や OS の完全な隔離は行っていない。特に lvl1 の平方根と lvl3 の逆元用べき乗の数 % の差は変動しうる。lvl1 平方根はビルドと並行した測定では僅かに遅くなったため、改善を重視する対象は逆元用べき乗と Fp2 平方根である。表はビルド・統合テストと重ならない測定の結果。

平方根は奇数冪テーブルを持つため一時領域が増える。ソース上の Fp 配列の合計は lvl1 が 192 bytes、lvl3 が 720 bytes、lvl5 が 1,152 bytes（従来の平方根は 64/96/128 bytes）。実際のスタック割り当てはコンパイラに依存する。

全体の署名・検証の高速化率は測定していない。単体測定の改善率をそのまま全体に適用することはできない。

**再現**

変更前は `708ac89` の `src/gf/ref` と同じ Fp ソースで、当該ターン開始時に `/tmp/sqisign-fixed-exp-baseline/lvl{1,3,5}` に保存した。保存済みディレクトリからは次で再測定できる。

```sh
python3 scripts/bench_fp_fixed.py \
    --baseline /tmp/sqisign-fixed-exp-baseline \
    --output /tmp/fp-fixed-exponent-results.json
```

別の環境では変更前コミットを別ディレクトリにチェックアウトし、その `src/gf/ref` を `--baseline` に指定する。ベンチマークスクリプトは両方に現在のヘッダを使用するため、同じ API と表現の実装間で比較するためのもの。x86-64 Linux 用で、ビルドは一時ディレクトリに作成する。

**検証**

- `--check` による生成ファイルの再現性と、生成時の整数指数の検証。
- 各レベルの Fp・Fp2 テスト 1,000 回。共通の固定指数回帰テストでは 0、1、p−1 と乱数について、通常の二進法によるべき乗と比較し、`fp_exp3div4` の入出力が同じ領域の場合も確認した。
- ベンチマークでコンパイルした変更前後の各実装について、境界値 3 個と乱数 64 個の結果を Python の多倍長整数による剰余累乗と照合。
- 鍵生成・署名・検証の統合テストを各レベル 100 回実行し、全レベルで成功した。
